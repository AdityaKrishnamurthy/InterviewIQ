# Plan 013 — Custom Company Personas

## Goal
Let users define their own company persona by pasting a job description (JD). The AI analyzes the JD to extract key requirements, focus areas, and evaluation criteria, then tailors all interview questions to that specific JD. Custom personas are saved per user and selectable alongside the built-in personas (Google, Amazon, Startup, General).

## Prerequisites
Plan 012 Done. The persona system (`PERSONAS` object in `adaptiveEngine.js`), `InterviewSession.jsx` persona selector, and `Session` model are functional.

## Steps

### Step Group 1: Server — Custom Persona Model & CRUD
**Files touched:** `server/src/models/CustomPersona.js`, `server/src/routes/persona.js`, `server/src/server.js`
**What to do:**
1. Create `CustomPersona` Mongoose model:
   ```
   userId         ObjectId (ref: User, required)
   name           String (required, e.g., "Meta L5 Frontend")
   companyName    String (required, e.g., "Meta")
   jobDescription String (required, the raw JD text, max 5000 chars)
   extractedFocus Object:
     - keySkills        [String]  — top skills/technologies from the JD
     - focusAreas       [String]  — main interview focus areas (e.g., "System Design", "React Performance")
     - evaluationStyle  String    — how to evaluate (e.g., "emphasis on scalability and production readiness")
     - roleLevel        String    — extracted seniority (e.g., "Senior", "Staff", "Entry")
     - systemPrompt     String    — generated system prompt for the AI interviewer
   createdAt      Date
   ```
2. Create `routes/persona.js` with:
   - `POST /api/persona` — Create a custom persona:
     - Accepts `name`, `companyName`, `jobDescription`.
     - Calls Groq AI to analyze the JD and extract `keySkills`, `focusAreas`, `evaluationStyle`, `roleLevel`, and generate a tailored `systemPrompt` (interviewer instructions for this specific JD).
     - Saves the `CustomPersona` document.
     - Returns the created persona.
   - `GET /api/persona` — List all custom personas for the authenticated user.
   - `DELETE /api/persona/:id` — Delete a custom persona.
3. Mount the route in `server.js`: `app.use('/api/persona', personaRoutes)`.
**Verification:** Create a custom persona via `POST /api/persona` with a real JD — extracted skills and focus areas are relevant. List and delete work.

### Step Group 2: Server — Integrate Custom Personas into Adaptive Engine
**Files touched:** `server/src/services/adaptiveEngine.js`, `server/src/routes/session.js`
**What to do:**
1. Update `generateInitialQuestion()`:
   - Accept an optional `customPersona` parameter (the `CustomPersona` document).
   - If provided, use `customPersona.extractedFocus.systemPrompt` as the AI system prompt instead of the built-in persona prompt.
   - Inject `customPersona.extractedFocus.keySkills` and `customPersona.extractedFocus.focusAreas` into the question generation context.
2. Update `evaluateAndGenerateFollowup()`:
   - Accept an optional `customPersona` parameter.
   - If provided, prepend the custom system prompt and evaluation criteria to the AI prompt.
3. Update `POST /api/session/start`:
   - Accept optional `customPersonaId` from the request body.
   - If provided, fetch the `CustomPersona` document and pass it to `generateInitialQuestion()`.
   - Store `customPersonaId` on the Session document.
   - Set `companyPersona` to `'Custom'` on the session.
4. Update `POST /api/session/answer`:
   - If the session has a `customPersonaId`, fetch the persona and pass it to `evaluateAndGenerateFollowup()`.
5. Add `customPersonaId` (ObjectId, optional) to `SessionSchema` and add `'Custom'` to the `companyPersona` enum.
**Verification:** Start a session with a custom persona — initial question references JD-specific skills. Follow-up questions stay tailored to the JD.
