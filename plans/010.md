# Plan 010 — Code Editor Panel

## Goal
Embed a live code editor (CodeMirror 6) into the interview session for DSA-style coding questions. When the AI interviewer asks a coding problem (especially under the Google persona), the candidate writes actual code in a syntax-highlighted editor. The AI evaluates the submitted code for correctness, time/space complexity, edge-case handling, and code style — not just a text explanation.

## Prerequisites
Plan 009 Done. `InterviewSession.jsx` and `POST /api/session/answer` are fully functional. The adaptive engine (`adaptiveEngine.js`) generates questions and evaluates answers.

## Steps

### Step Group 1: Client — CodeMirror Editor Component
**Files touched:** `client/src/components/CodeEditor.jsx`, `client/src/index.css`
**What to do:**
1. Create a reusable `<CodeEditor>` component wrapping CodeMirror 6:
   - Props:
     - `value` (string): initial code content.
     - `onChange` (callback): fired on every edit with the new code string.
     - `language` (string): one of `javascript`, `python`, `java`, `cpp`. Defaults to `javascript`.
     - `readOnly` (boolean): disables editing (for replay/review).
     - `height` (string): CSS height, defaults to `300px`.
   - Features:
     - Syntax highlighting using the appropriate language extension.
     - Dark theme using `@codemirror/theme-one-dark` (matches the app's dark UI).
     - Line numbers enabled.
     - Bracket matching, auto-close brackets.
     - Tab key inserts spaces (2-space indent).
     - Placeholder text: `// Write your solution here...`.
   - Mount/unmount cleanly using `useEffect` and `useRef`.
2. CSS additions:
   - `.code-editor-wrapper`: border, border-radius matching `var(--radius-md)`, overflow hidden.
   - `.code-editor-wrapper .cm-editor`: ensure font is `'JetBrains Mono', 'Fira Code', monospace` at `14px`.
   - `.code-editor-wrapper .cm-focused`: border glow using `var(--primary)`.
**Verification:** Render `<CodeEditor>` in isolation — syntax highlighting, line numbers, and theme work correctly.

### Step Group 2: Client — Language Selector & Code Mode Toggle
**Files touched:** `client/src/pages/InterviewSession.jsx`
**What to do:**
1. Add a **Code Mode toggle** in the answer input area:
   - A segmented control or icon-toggle: `📝 Text` / `💻 Code`.
   - When "Code" is selected, replace the `<textarea>` with `<CodeEditor>`.
   - When "Text" is selected, show the original textarea (existing behavior).
2. When Code Mode is active, show a **language selector dropdown** above the editor:
   - Options: JavaScript, Python, Java, C++.
   - Default: JavaScript.
   - Styled as a small pill dropdown matching the design system.
3. State management:
   - `codeMode` (boolean): whether code editor is shown.
   - `codeLanguage` (string): selected language.
   - `codeContent` (string): current editor content.
   - When submitting in code mode, send `answer` as the code string prefixed with a language tag, e.g.:
     ```
     [CODE:javascript]
     function twoSum(nums, target) { ... }
     ```
   - This prefix tells the server's adaptive engine to evaluate it as code.
4. Auto-detect coding questions:
   - When a new AI interviewer message contains keywords like "write a function", "implement", "code a solution", "algorithm", "LeetCode", automatically switch to code mode and show a subtle hint: "💡 Code editor activated — write your solution below."
**Verification:** Toggle between text and code mode. Write code in the editor. Submit — answer is sent with `[CODE:language]` prefix.

### Step Group 3: Server — Code-Aware Answer Evaluation
**Files touched:** `server/src/services/adaptiveEngine.js`
**What to do:**
1. In `evaluateAndGenerateFollowup()`, detect if the candidate answer starts with `[CODE:language]`.
2. If it does, modify the evaluation system prompt to instruct the LLM to evaluate the answer **as source code**:
   - Evaluate for:
     - **Correctness**: Does the code solve the problem? Are edge cases handled?
     - **Time Complexity**: What is the Big-O? Is it optimal?
     - **Space Complexity**: Extra memory usage.
     - **Code Quality**: Readability, naming conventions, comments.
     - **Edge Cases**: Null/empty inputs, boundary values, overflow.
   - Score 1–5 based on a weighted rubric:
     - Correctness: 40%
     - Optimal complexity: 25%
     - Edge cases: 20%
     - Code quality: 15%
   - Generate specific feedback referencing lines or logic in the code (e.g., "Your base case on line 3 doesn't handle empty arrays").
   - The follow-up question should probe the candidate on their approach: "Can you optimize the time complexity?" or "What happens if the input is negative?"
3. If the answer does NOT start with `[CODE:]`, evaluate as before (text-based).
**Verification:** Submit a code answer via the API — evaluation references code-specific criteria (complexity, edge cases). Score is reasonable.

### Step Group 4: Client — Code Answer Display in Chat
**Files touched:** `client/src/pages/InterviewSession.jsx`
**What to do:**
1. When rendering candidate messages in the conversation log, detect if the message content starts with `[CODE:language]`.
2. If so, strip the prefix and render the code using `<CodeEditor readOnly={true} language={lang} value={code} />` inside the chat bubble instead of plain text.
3. This gives syntax-highlighted code display in the conversation history.
4. For non-code messages, render as before (plain text with `white-space: pre-wrap`).
**Verification:** Submit a code answer — it appears syntax-highlighted in the chat log. Text answers still render normally.
