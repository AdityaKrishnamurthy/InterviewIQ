# Plan 012 — Session Replay / Transcript View

## Goal
Let users revisit the full Q&A transcript from any past completed session. Each question–answer pair is displayed with the inline AI evaluation, score badge, difficulty at that point, and timestamp. Candidates can study their weak answers and see exactly what the AI feedback was.

## Prerequisites
Plan 011 Done. Session data already stores all messages with `role`, `content`, `score`, `evaluation`, `difficulty`, and `timestamp`. The `GET /api/session/:id` endpoint returns the full session.

```bash
test -f "server/src/routes/session.js" && test -f "client/src/pages/FinalReport.jsx" && echo "Ready" || echo "Drift detected"
```

## Steps

### Step Group 1: Client — Transcript Page
**Files touched:** `client/src/pages/SessionTranscript.jsx`, `client/src/App.jsx`
**What to do:**
1. Create a new page `SessionTranscript.jsx` at route `/transcript/:sessionId`.
2. On mount, fetch `GET /api/session/:sessionId` to get the full session data.
3. Render a structured transcript view:
   - **Header section**:
     - Session metadata: persona badge, target role, date, status, overall score, total Q&A turns.
     - "Back to Report" button linking to `/report/:sessionId`.
     - "Back to Dashboard" button linking to `/dashboard`.
   - **Q&A Pair Cards**: For each interviewer→candidate message pair, render a card:
     - **Question block** (left-aligned):
       - `🤖 AI Interviewer` label with difficulty badge (`Easy` / `Medium` / `Hard`, color-coded).
       - Question text with `white-space: pre-wrap`.
       - Timestamp (relative or absolute).
     - **Answer block** (right-aligned, indented):
       - `👤 Candidate` label.
       - Answer text. If the answer starts with `[CODE:language]`, render it in a read-only `<CodeEditor>` (from Plan 010, if available) or a `<pre><code>` block with monospace styling.
       - **Score badge**: large colored circle (1–5 scale). Green ≥ 4, Yellow 3, Red ≤ 2.
       - **AI Evaluation feedback**: shown in a collapsible section below the answer (expanded by default for scores ≤ 2, collapsed for scores ≥ 4). Styled as a subtle bordered box with `💬 AI Feedback:` label.
       - **Time spent** badge (if available from timed mode).
   - **Weak Answer Highlights**: Questions where `score ≤ 2` get a left border accent in `var(--error)` and a "⚠️ Weak Area" label, making them visually scannable.
4. Add a **filter bar** at the top:
   - Filter by score: "All" / "Weak (≤2)" / "Average (3)" / "Strong (≥4)".
   - Clicking a filter scrolls to and highlights matching Q&A pairs, dimming the rest.
5. Empty state: if session has no candidate messages, show "This session has no answers recorded."
6. Loading state: skeleton placeholder while fetching.
**Verification:** Navigate to `/transcript/:id` for a completed session — all Q&A pairs render with scores, evaluation feedback, and difficulty badges.

### Step Group 2: Client — Navigation Links to Transcript
**Files touched:** `client/src/pages/FinalReport.jsx`, `client/src/components/SessionHistoryList.jsx`
**What to do:**
1. In `FinalReport.jsx`, add a "📜 View Full Transcript" button in the header nav area (next to "Export PDF" and "New Session").
   - Links to `/transcript/:sessionId`.
2. In `SessionHistoryList.jsx` (from Plan 008), add a secondary action on each completed session card:

   - Opens `/transcript/:sessionId`.
3. Add the route to `App.jsx`:
   ```jsx
   <Route path="/transcript/:sessionId" element={<PrivateRoute><SessionTranscript /></PrivateRoute>} />
   ```
**Verification:** Click "View Full Transcript" from a report page — navigates to the transcript. Click "Transcript" from the session history list — same.

### Step Group 3: Client — Transcript Polish
**Files touched:** `client/src/pages/SessionTranscript.jsx`, `client/src/index.css`
**What to do:**
1. **Print-friendly layout**: Add `@media print` styles that hide the filter bar and navigation, format Q&A pairs cleanly for printing.
2. **Scroll-to-weak**: Add a floating "Jump to Weak Answers" button (bottom-right corner) that scrolls to the first Q&A pair with `score ≤ 2`. Only visible if weak answers exist.
3. **Smooth animations**: Fade-in each Q&A pair with a staggered delay on page load.
4. **Responsive**: Single-column layout on mobile with full-width cards.
5. CSS classes:
   - `.transcript-card`: session metadata header card.
   - `.qa-pair`: container for one question-answer pair.
   - `.qa-pair.weak`: left border accent `var(--error)`.
   - `.qa-pair.strong`: left border accent `var(--success)`.
   - `.qa-score-badge`: circular score indicator.
   - `.qa-evaluation`: collapsible feedback section.
   - `.transcript-filter-bar`: horizontal filter pills.
   - `.jump-to-weak-btn`: floating action button.
**Verification:** Page looks polished. Filter works. Print preview is clean. Mobile layout is usable.
