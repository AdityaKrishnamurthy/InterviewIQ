# Plan 008 — Interview History & Progress Dashboard

## Goal
Build a session history page showing all past interview sessions in a visual timeline, with score trend charts (sparklines) so candidates can track their improvement across multiple sessions. Integrate it into the main Dashboard as the primary landing view.

## Prerequisites
Plan 007 Done. The `GET /api/session` endpoint already returns all user sessions sorted by `updatedAt`. The `Session` model already stores `overallScore`, `companyPersona`, `targetRole`, `status`, `createdAt`, `messages`, and `skillConfidence`.


## Steps

### Step Group 1: Server — Session History & Stats Endpoint
**Files touched:** `server/src/routes/session.js`
**What to do:**
1. Add `GET /api/session/history` endpoint (auth-protected) that returns:
   - All user sessions sorted by `createdAt` ascending (chronological order for charting).
   - For each session, return a lightweight projection: `_id`, `companyPersona`, `targetRole`, `status`, `overallScore`, `currentDifficulty`, `createdAt`, `updatedAt`, question count (`messages` length filtered by `role === 'candidate'`).
   - An aggregate `stats` object computed on the server:
     - `totalSessions`: count of all sessions.
     - `completedSessions`: count where `status === 'completed'`.
     - `averageScore`: mean of all `overallScore` values (completed sessions only).
     - `bestScore`: highest `overallScore`.
     - `scoreTimeline`: array of `{ date, score, persona }` objects for charting (one entry per completed session, chronological).
     - `personaBreakdown`: object mapping each persona to its count and average score.
**Verification:** `curl` or Postman confirms the endpoint returns the correct shape with `stats` and `sessions` arrays.

### Step Group 2: Client — Score Trend Chart Component
**Files touched:** `client/src/components/ScoreTrendChart.jsx`
**What to do:**
1. Create a pure SVG sparkline/line chart component (no external chart libraries — keep zero new dependencies).
2. Props: `data` (array of `{ date, score, persona }`), `width`, `height`.
3. Render:
   - X-axis: session dates (abbreviated, e.g., "Aug 5").
   - Y-axis: score 0–5 with gridlines at 1, 2, 3, 4, 5.
   - Line path connecting data points with smooth curves (`cubic bezier` or `catmull-rom` interpolation).
   - Colored data-point dots: green (≥ 4), yellow (3–3.9), red (< 3).
   - Hover tooltip showing date, score, and persona for each dot.
   - A subtle gradient fill under the line for visual polish.
4. Handle empty state (< 2 data points): show a friendly "Complete more sessions to see your progress trend" message instead of a broken chart.
5. Follow `DESIGN.md` color tokens: `var(--primary)`, `var(--success)`, `var(--warning)`, `var(--error)`.
**Verification:** Component renders correctly with mock data; hover tooltips work.

### Step Group 3: Client — Session History List Component
**Files touched:** `client/src/components/SessionHistoryList.jsx`
**What to do:**
1. Create a session history list component that renders each past session as a card/row.
2. Each session card shows:
   - Persona badge (colored by persona type).
   - Target role.
   - Date (relative, e.g., "2 hours ago" or "Aug 3, 2026").
   - Status badge: "Completed" (green) / "Active" (yellow).
   - Score display (e.g., "4.2 / 5.0") with color coding.
   - Final difficulty level badge.
   - Number of Q&A turns.
3. Clicking a completed session navigates to `/report/:sessionId`.
4. Clicking an active session navigates to `/interview` (with a note that resuming is not yet supported — future feature).
5. Empty state: friendly card with "No interview sessions yet. Start your first one!" and a CTA button linking to `/interview`.
6. Follow `DESIGN.md` styling — use `var(--bg-surface)`, `var(--border-color)`, card radius, hover transitions.
**Verification:** List renders with real session data; navigation works correctly on click.
