# Plan 011 — Timed Interview Mode

## Goal
Add a configurable countdown timer to interview sessions (30 / 45 / 60 minutes). Track time spent on each question. The final report includes per-question time analytics, flags questions where the candidate stalled, and shows a time distribution breakdown.

## Prerequisites
Plan 010 Done. The interview session flow (`start` → `answer` → `complete` → `report`) is fully functional.

## Steps

### Step Group 1: Server — Schema & Timer Fields
**Files touched:** `server/src/models/Session.js`, `server/src/routes/session.js`
**What to do:**
1. Add fields to `SessionSchema`:
   - `timerEnabled` (Boolean, default `false`): whether timed mode is on.
   - `timerDuration` (Number): total session time in seconds (e.g., 1800 for 30 min).
   - `startedAt` (Date): actual start time of the interview (set when first question is generated).
   - `endedAt` (Date): when the session was completed (either manually or by timer expiry).
2. Add a `timeSpent` field to `MessageSchema`:
   - `timeSpent` (Number, default `null`): seconds the candidate took to answer this question. Only populated on `role: 'candidate'` messages.
3. Update `POST /api/session/start`:
   - Accept optional `timerEnabled` (boolean) and `timerDuration` (number, one of `1800`, `2700`, `3600`) from the request body.
   - Set `startedAt` to `new Date()` when the session starts.
4. Update `POST /api/session/answer`:
   - Accept optional `timeSpent` (number) from the request body.
   - Store it on the candidate message.
5. Update `POST /api/session/:id/complete`:
   - Set `endedAt` to `new Date()`.
**Verification:** Start a timed session — `timerEnabled`, `timerDuration`, and `startedAt` are stored. Submit an answer with `timeSpent` — value is persisted.

### Step Group 3: Client — Live Countdown Timer Display
**Files touched:** `client/src/pages/InterviewSession.jsx`, `client/src/hooks/useTimer.js`, `client/src/index.css`
**What to do:**
1. Create a `useTimer(durationSeconds, startedAt, enabled)` hook:
   - Computes `remainingSeconds` by comparing `Date.now()` against `startedAt + durationSeconds`.
   - Updates every second using `setInterval`.
   - Returns `{ remainingSeconds, isExpired, formattedTime }`.
   - `formattedTime`: string in `MM:SS` format.
   - `isExpired`: true when `remainingSeconds <= 0`.
   - Cleans up the interval on unmount.
2. Track per-question time:
   - Record `questionStartTime` (local state timestamp) when a new interviewer question arrives.
   - When the candidate submits an answer, compute `timeSpent = (Date.now() - questionStartTime) / 1000` and include it in the API request.
3. Display the timer in the top status bar when `timerEnabled`:
   - Position: right side of the status bar, next to the difficulty badge.
   - Appearance:
     - `> 5 min left`: white text, normal display.
     - `1–5 min left`: `var(--warning)` color, subtle pulse animation.
     - `< 1 min left`: `var(--error)` color, faster pulse, larger font.
   - Format: `⏱️ 23:45` (minutes:seconds).
4. When timer expires (`isExpired === true`):
   - Show a modal overlay: "⏰ Time's Up! Your interview session has ended."
   - Auto-call the session complete endpoint (`POST /api/session/:id/complete`).
   - Navigate to the report page after completion.
   - Disable the answer input and submit button.
5. CSS:
   - `.timer-display`: flexbox, monospace font, aligned right.
   - `.timer-warning`: `var(--warning)` color + `@keyframes timer-pulse`.
   - `.timer-critical`: `var(--error)` color + faster pulse.
   - `.timer-expired-overlay`: full-screen semi-transparent overlay with centered modal.
**Verification:** Start a 30-min timed session. Timer counts down in real time. At < 5 min, color changes to yellow. At < 1 min, turns red and pulses. At 0, overlay appears and session auto-completes.

### Step Group 4: Client — Per-Question Time Display in Chat
**Files touched:** `client/src/pages/InterviewSession.jsx`
**What to do:**
1. For each candidate message in the chat log, if `timeSpent` exists, show a small time badge below the message bubble:

     - `> 300s`: `var(--error)` (stalled — will be flagged in report).
2. Only show time badges if the session has `timerEnabled === true`.
**Verification:** Submit answers in a timed session — time badges appear under each candidate message with correct formatting and colors.

### Step Group 5: Server & Client — Time Analytics in Report
**Files touched:** `server/src/routes/session.js`, `client/src/pages/FinalReport.jsx`
**What to do:**
1. **Server** — In the `GET /api/session/:id/report` endpoint, compute and include time analytics when `timerEnabled`:
   - `totalTimeUsed`: sum of all `timeSpent` values (seconds).
   - `averageTimePerQuestion`: mean of `timeSpent` values.
   - `fastestAnswer`: `{ question (truncated), timeSpent }`.
   - `slowestAnswer`: `{ question (truncated), timeSpent }`.
   - `stalledQuestions`: array of questions where `timeSpent > 180s`, with the question text and time.
   - `timeDistribution`: array of `{ questionIndex, question (truncated to 80 chars), timeSpent, difficulty }` for charting.
2. **Client** — Add a new tab to `FinalReport.jsx`:
   - Tab label: `⏱️ Time Analytics` (only visible if the session was timed).
   - Content:
     - **Summary stats row**: Total Time Used, Avg Time/Question, Fastest, Slowest (4 stat cards).
     - **Time Distribution Bar Chart**: horizontal bars per question, colored by time thresholds (green/yellow/red). Pure SVG, no dependencies.
     - **Stalled Questions Alert**: if any questions took > 3 min, show them in a warning box with the question text and time.
**Verification:** Complete a timed session. View the report. "Time Analytics" tab shows correct stats, bar chart, and stalled question flags.
