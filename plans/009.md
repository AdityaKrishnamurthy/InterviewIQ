# Plan 009 — Voice-Based Interview Mode

## Goal
Add a voice-based interview mode using the browser-native Web Speech API (SpeechRecognition for STT and SpeechSynthesis for TTS). Candidates can toggle between text and voice mode during an interview session. In voice mode, the AI interviewer reads questions aloud and the candidate speaks their answers, creating a realistic mock interview experience. Zero new npm dependencies.

## Prerequisites
Plan 008 Done. The `InterviewSession.jsx` page and the `POST /api/session/answer` + `POST /api/session/start` server routes are fully functional.

## Steps

### Step Group 1: Client — Speech Utilities Hook
**Files touched:** `client/src/hooks/useSpeech.js`
**What to do:**
1. Create a custom React hook `useSpeech()` that encapsulates both STT and TTS:
   - **TTS (Text-to-Speech):**
     - `speak(text)`: Speaks the given text using `window.speechSynthesis`.
     - Select a natural-sounding English voice from `speechSynthesis.getVoices()` (prefer voices with `lang` starting with `en-`; prefer `Google` or `Microsoft` voices if available; fallback to first `en-*` voice).
     - `rate`: 0.95 (slightly slower than default for interview clarity).
     - `pitch`: 1.0.
     - `stopSpeaking()`: Cancels any ongoing speech.
     - `isSpeaking`: boolean state tracking whether TTS is currently active.
   - **STT (Speech-to-Text):**
     - Use `webkitSpeechRecognition` or `SpeechRecognition` (browser-native).
     - `startListening()`: Begins continuous speech recognition. Sets `isListening` to true.
     - `stopListening()`: Stops recognition. Sets `isListening` to false.
     - `transcript`: string state that accumulates recognized text (using `interimResults` for live preview and `results[i].isFinal` for confirmed text).
     - `resetTranscript()`: Clears the accumulated transcript.
     - `isListening`: boolean state.
     - `error`: string state for recognition errors (e.g., "not-allowed", "no-speech").
     - Configure `recognition.continuous = true` and `recognition.interimResults = true` for real-time feedback.
     - `recognition.lang = 'en-US'`.
   - **Feature Detection:**
     - `isSupported`: boolean — `true` if both `SpeechRecognition` and `speechSynthesis` are available in the browser.
     - If not supported, all methods are no-ops and `isSupported` is `false`.
2. Handle edge cases:
   - Auto-restart recognition if it stops unexpectedly (common in Chrome after ~60s of silence).
   - Clean up on component unmount (`recognition.abort()`, `speechSynthesis.cancel()`).
   - Handle `onerror` events gracefully (microphone denied, network error, etc.).
**Verification:** Import hook in a test component, call `speak("Hello")` — audio plays. Call `startListening()`, speak into mic — transcript updates in real time.

### Step Group 2: Client — Voice Mode UI in InterviewSession
**Files touched:** `client/src/pages/InterviewSession.jsx`, `client/src/index.css`
**What to do:**
1. Import and use the `useSpeech()` hook.
2. Add a **Voice Mode Toggle** button in the top status bar (next to the difficulty badge area):
   - Toggle between 🎤 Voice Mode and ⌨️ Text Mode.
   - When voice mode is enabled, show a prominent indicator (e.g., pulsing microphone icon with "Voice Mode Active" label).
   - Persist the mode choice in React state (no need to persist across sessions).
3. **When Voice Mode is ON:**
   - **TTS — Auto-read AI questions:**
     - When a new interviewer message arrives (after `setSession(data.session)`), automatically call `speak(newQuestion)` to read the question aloud.
     - Show a small "🔊 Speaking..." indicator on the AI message bubble while TTS is active.
     - Add a "🔇 Stop" button on the AI message to cancel TTS mid-speech.
   - **STT — Voice answer input:**
     - Replace the text `<textarea>` with a voice recording interface:
       - Large circular microphone button (centered, prominent, using `var(--primary)` color).
       - Three states with visual feedback:
         1. **Idle**: Mic icon, label "Tap to speak your answer".
         2. **Listening**: Pulsing red ring animation around the mic, label "Listening... speak now".
         3. **Processing**: Spinner, label "Submitting answer...".
       - Show the **live transcript** below the mic button in a semi-transparent text area (read-only), updating in real time as the candidate speaks.
       - A "Done" button to stop listening and finalize the transcript.
       - A "Reset" button to clear and re-record.
     - On "Done":
       - Stop STT.
       - Copy the final transcript into the answer field.
       - Auto-submit the answer (call `handleSendAnswer` programmatically).
   - **Workflow per Q&A turn in voice mode:**
     1. AI question arrives → TTS reads it aloud → "🔊 Speaking..." indicator.
     2. TTS finishes → Auto-start STT → mic button pulses, "Listening..." state.
     3. Candidate speaks → live transcript updates.
     4. Candidate clicks "Done" → STT stops → answer submitted → AI evaluates.
     5. Next question arrives → repeat from step 1.
4. **When Voice Mode is OFF:**
   - Everything works exactly as it does today (text textarea + submit button). No changes.
5. **CSS additions in `index.css`:**
   - `.voice-toggle-btn`: styled toggle button with smooth transition.
   - `.mic-button`: large circular button (80px diameter), centered, with hover/active states.
   - `.mic-button.listening`: pulsing red ring animation using `@keyframes pulse-ring`.
   - `.mic-button.speaking`: subtle blue glow animation.
   - `.voice-transcript-preview`: semi-transparent read-only text area for live transcript.
   - `.voice-indicator`: small badge/label for "Voice Mode Active", "Speaking...", "Listening...".
**Verification:** Toggle voice mode on. AI question is spoken aloud. Click mic, speak an answer — live transcript appears. Click "Done" — answer is submitted and next question is spoken.

### Step Group 3: Client — Voice Mode Polish & Edge Cases
**Files touched:** `client/src/pages/InterviewSession.jsx`, `client/src/hooks/useSpeech.js`
**What to do:**
1. **Browser compatibility fallback:**
   - If `isSupported` is `false`, disable the voice toggle button and show a tooltip: "Voice mode requires Chrome, Edge, or Safari".
   - The toggle button should appear greyed out with a `title` attribute explaining the requirement.
2. **Microphone permission handling:**
   - If STT returns a "not-allowed" error, show an inline alert: "Microphone access denied. Please allow microphone access in your browser settings."
   - Provide a "Retry" button to re-request permission.
3. **Silence timeout:**
   - If no speech is detected for 15 seconds during STT, auto-stop listening and show: "No speech detected. Tap the mic to try again."
4. **Long answer handling:**
   - If the transcript exceeds 2000 characters, show a warning: "Answer is getting long — consider wrapping up."
5. **TTS queue management:**
   - If a new question arrives while the previous one is still being spoken, cancel the old speech and start the new one.
6. **Keyboard shortcut:**
   - `Space` key toggles listening start/stop when voice mode is on and the textarea is not focused.
   - Show a subtle hint: "Press Space to start/stop recording".
7. **Visual polish:**
   - Smooth transitions between listening/idle/processing states.
   - Audio waveform animation (CSS-only, using multiple animated bars) around the mic button while listening.
**Verification:** Test in Chrome and a non-supporting browser (Firefox Private). Deny mic permission and verify error message. Wait 15s silently and verify timeout. Test Space shortcut.
