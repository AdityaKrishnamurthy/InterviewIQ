# Plan 016 — Voice Mode Reliability & Cross-Browser Fallback

## Goal
Voice mode (Plan 009) works in Chrome but silently fails in Brave. Root cause: `useSpeech.js` relies exclusively on `webkitSpeechRecognition`, which in every Chromium browser streams mic audio to Google's remote recognition backend rather than running on-device. Brave blocks that backend by default, so recognition errors out immediately (`network` / `service-not-allowed`) even with mic permission granted — and the same failure mode hits Firefox, Vivaldi, Arc, and any de-Googled Chromium build. Add a server-side transcription fallback (Groq's hosted Whisper endpoint, already an installed dependency via `groq-sdk`) so voice mode works identically across all browsers, with the client transparently switching to it whenever the native engine is unsupported or gets blocked at runtime. Zero new npm dependencies.

## Prerequisites
Plan 009 Done. `GROQ_API_KEY` set in `.env.local` (already required for `server/src/services/aiProvider.js`'s text completions).

## Steps

### Step Group 1: Server — Groq Whisper Transcription Endpoint
**Files touched:** `server/src/services/aiProvider.js`, `server/src/routes/speech.js` (new), `server/src/server.js`
**What was done:**
1. `aiProvider.js`: added `transcribeAudio(buffer, filename, mimetype)` using the existing `getGroqClient()` plus `groq-sdk`'s `toFile` upload helper, calling `groq.audio.transcriptions.create({ file, model: GROQ_WHISPER_MODEL, language: 'en', response_format: 'json' })`. `GROQ_WHISPER_MODEL` defaults to `whisper-large-v3-turbo` and is env-configurable, following the same pattern the `GROQ_MODEL`/`GEMINI_MODEL` config fix (commit `0ed62bc`) just established so a future model decommission is a config change, not a patch. Throws a clear error when no Groq client is configured.
2. New `server/src/routes/speech.js`: `POST /api/speech/transcribe`, behind `authMiddleware`, `multer({ storage: memoryStorage() })` (no need to persist audio to disk, unlike resume PDFs), 10MB limit, single `audio` field. Returns `{ transcript }`; 503 if transcription is unconfigured, 500 on failure.
3. Mounted at `/api/speech` in `server.js` alongside the existing route mounts.

### Step Group 2: Client — MediaRecorder Fallback in `useSpeech`
**Files touched:** `client/src/hooks/useSpeech.js`
**What was done:**
1. `isSttSupported` now also true when `MediaRecorder` + `getUserMedia` exist, even without native `SpeechRecognition` — this is what previously kept the voice toggle disabled on Brave/Firefox.
2. Hook signature is now `useSpeech(token)` — the auth token is needed to call the new transcription endpoint.
3. `startListening()` uses the native engine first when available and not yet known-broken (tracked via `nativeBrokenRef`, persists for the rest of the session once tripped). If native `onerror` fires `'service-not-allowed'` or `'network'` — the Brave-signature failures — the hook aborts native recognition and switches to the MediaRecorder fallback transparently (no error surfaced) if the user was still trying to listen. A stale-closure-safe ref (`startFallbackRecordingRef`, mirroring the existing `isListeningRef` pattern) lets the mount-effect's `onerror` handler call the fallback starter without re-running the whole init effect.
4. Fallback path: `getUserMedia` → `MediaRecorder` (mimeType picked from `audio/webm;codecs=opus` / `audio/webm` / `audio/mp4` via `isTypeSupported`) → on `stop()`, POSTs the recorded Blob as `multipart/form-data` to `/api/speech/transcribe`, sets the new `isTranscribing` state during the round-trip (with a 30s safety timeout mirroring the existing 20s TTS safety timer), and writes the result into `transcript` on success.
5. New `sttEngine` state (`'native' | 'fallback' | 'none'`) exposed from the hook so the UI can show which engine is active. `'not-allowed'` (real permission denial) stays a terminal error for both engines since both require mic access.

### Step Group 3: Client — Wire Fallback Into `InterviewSession` UI
**Files touched:** `client/src/pages/InterviewSession.jsx`, `client/src/index.css`
**What was done:**
1. `useSpeech(token)` now receives the auth token from the page.
2. Error banner now branches on `'not-allowed'`, `'transcription-failed'`, and `'unsupported'` with distinct copy — an invisible native→fallback engine swap sets none of these, so it never triggers an alarming banner for something that still works.
3. Added a small `.stt-engine-badge` ("☁️ Server transcription") shown only when `sttEngine === 'fallback'`, plus an `isTranscribing` status label/spinner inserted into the existing state sequence (idle → listening → **transcribing** → submitting), and disabled the mic button + Space shortcut while a transcription is in flight.
4. Corrected the voice-toggle's disabled tooltip (previously the inaccurate "Voice mode requires Chrome, Edge, or Safari") since the fallback now covers effectively all modern browsers.
5. Added `.stt-engine-badge` and `.mic-button.transcribing` CSS, reusing existing tokens (`var(--secondary)`, existing pulse-ring pattern) rather than introducing new ones.
